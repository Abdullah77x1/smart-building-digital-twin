# Explain the ML Model in a Presentation

## 1. One model, twelve predictions

Our project uses ONE feed-forward neural network with a shared feature-processing section and three output heads: HVAC electrical power, indoor temperature, and occupancy. Every head outputs four values (at 5, 10, 15, and 30 minutes in the future), so there are 3 × 4 = 12 outputs. The network has two hidden layers of 64 neurons each (modifiable in `train_multitask.py`).

## 2. What the model sees

At a given timestamp `t`, we take 10 current observations, six calendar features, and 20 lagged measurements (5 variables × 4 previous timestamps). That creates 36 input features. The lags cover the preceding 5, 15, 30 and 60 minutes.

**The future actual HVAC power, future temperature, and future occupancy are not inputs.** We create those columns only as correct answers for training and evaluation. We also exclude V2's `next_indoor_temp_c` field, which would otherwise leak the actual next-step temperature.

## 3. What is training?

For each training example, the network predicts 12 future values. We compare its guesses against the 12 recorded simulated answers and compute mean squared error (MSE). The Adam optimizer changes the network's learnable weights to reduce that error over successive examples and epochs. Because kW, °C, and people have different numerical scales, each input and each future target is standardized using means and standard deviations calculated exclusively from training years 2022–2023. All three output heads therefore contribute to a joint standardized loss.

## 4. What do the file extensions mean?

- `.py`: Python source code (defines data preprocessing, architecture, training and prediction)
- `.csv`: historical input data, example forecasts or error tables
- `.pt`: a **trained model checkpoint** containing the learned neural network weights, feature names, and normalization statistics. The dashboard later loads this file to predict without retraining.
- `.json`: training and evaluation results

## 5. How do we measure performance?

We evaluate **MAE** (mean absolute error) and **RMSE** (root mean squared error), separately for all 12 outputs. We compare the network with a very simple baseline: assume the value 5–30 minutes into the future will equal the current value. For slowly changing temperatures or occupancy, this can be hard to beat at +5 minutes.

We choose the number of training epochs using 2024 validation data, and evaluate 2025 separately after finalizing that model. The same 2025 year can be subdivided into four seasons to reveal periods where prediction is harder.

## 6. What does this not prove?

All input and target observations are generated by our own V2 simulator, so the network is learning **the synthetic simulator's patterns**. Good accuracy does not mean the system is accurate on real buildings. The first model is also a **passive forecaster**: it predicts under the normal controller behavior in the generated history. It cannot yet reliably answer counterfactual queries such as "What if I change the HVAC setpoint from 24°C to 26°C?" unless we build and validate an action-conditioned response model, or use the simulator directly.

## 7. Suggested oral explanation

> We first programmed a simplified physics-based building simulator and generated four years of five-minute observations. We then developed a multi-task neural network using 36 current and historical features. Its shared neural network has three specialized heads that predict HVAC electrical power, indoor temperature and occupancy, each at four future times. We train on 2022–2023, validate on 2024, and test on 2025. We compare all results to a no-change forecasting baseline and report the limitations of fully simulated data.
